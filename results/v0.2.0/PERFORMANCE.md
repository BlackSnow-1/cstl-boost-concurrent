# Map 性能对比（2026-11-04）

## 结论

完整替换为官方 Boost 1.87.0 concurrent_flat_map 后，48 场景等权几何平均吞吐为直接 Boost 的 **1.002 倍（+0.2%）**，为压缩包原版的 **1.277 倍（+27.7%）**。这不是总耗时加权，也不是任意业务负载的预期收益。

**没有达成“所有场景完全复刻旧版性能”。** 48 个场景中，14 个比旧版慢超过 5%，主要是 64 热键和部分增长插入。没有删除这些样本，也没有改回 parallel-hashmap 来隐藏差距。

与直接 Boost 相比，42/48 个场景的中位数比值位于 0.95–1.05；其余场景仍按实记录，不能把几何平均接近 1 解释为每个场景都等同。

| 线程数 | 场景数 | CSTL / 直接 Boost（几何平均） | CSTL / 压缩包原版（几何平均） |
|---:|---:|---:|---:|
| 1 | 16 | 0.991x | 0.986x |
| 4 | 16 | 1.011x | 1.310x |
| 12 | 16 | 1.004x | 1.613x |

## 发现差距后的实现复核

1. 阅读并保留原 parallel-hashmap Map（`provenance/cstl/concurrent_unordered_map.hpp`），以及 Boost 的 `concurrent_flat_map.hpp`、`detail/foa/concurrent_table.hpp` 和 `rw_spinlock.hpp`。原版 16 分片 shared_mutex 与 Boost 容器级/槽组级自旋读写锁、全表扩容是不同设计；不能把其中一个的全部成本特征直接等同于另一个。
2. 初始适配按引用套 visitor，在 MSVC 汇编中发现读取路径额外间接访问。重新编写 `detail/map_value_visitor.hpp`：临时可复制回调直接保存在 visitor 内，左值和移动专属回调按引用保存；热点转发沿用 Boost 强制内联。没有修改 Boost 的探测、锁、内存序或扩容。
3. 分别以 uint64 和 string 键编译独立实验；读取、更新、插入三个 facade/native 函数对均被 MSVC `/OPT:ICF` 合并为相同地址。结果见 `results/codegen.json` 和 `results/codegen-string.json`，复现源码为 `tools/codegen.cpp`。证据限于这些探针及当前编译器，不覆盖任意回调或全部操作。
4. 将 benchmark 的负载字符串判断移出计时循环，以编译期负载分派运行正式矩阵；旧探索数据保留在 `results/exploratory/`，它们与编译/Debug 检查有重叠，不计入正式结论。

## 异常点独立复测

正式矩阵中，12 线程 string 更新的中位数为原生 Boost 的 0.868 倍，95% bootstrap 区间 [0.737, 0.961]。随后单独延长到目标 0.5 秒、每种实现 21 次，得到 **1.008 倍**，区间 **[0.996, 1.036]**；未复现原来的明显退步。原始数据均保留在 `results/recheck-string-update/`，不替换首次矩阵的数据。

这说明该短样本对运行调度、竞争和系统状态敏感；相同机器码证据也不等于任意一次吞吐读数必须相同。没有据此保证所有负载都达到 5% 等价。

## 测量条件与范围

- Windows x64，12 逻辑处理器；MSVC 19.44.35213，C++17，Release `/O2 /Ob2 /DNDEBUG`。源码、二进制 SHA 与环境记录见 `results/environment.json`。
- 同一可执行文件中包含三种实现：压缩包原 Map（仅命名空间/include 调整）、直接 Boost 与 CSTL。它们使用相同 Key/T、`std::hash<Key>`、预留策略及负载；直接 Boost 控制也按 mapped value 适配回调，不使用其不同的默认 boost::hash 来混淆比较。
- 48 场景：1/4/12 线程、uint64/string 键、65536 预置键及 64 热键；读取命中、未命中、更新、原子插入或更新、80/20 混合、删除重插、预留插入、不预留增长插入。
- 每场景先校准，随后每实现运行 11 次；每轮随机打乱实现顺序（固定 seed 20261104）。正式样本 **1584** 条；独立复测 **63** 条。计时包含工作线程启动后的执行及 join，排除容器预填充与键生成。
- 每次校验操作计数、可确定的值总和和插入结果，防止以错误数据获得更快结果。churn 的一次操作是“删除 + 重插”复合动作。插入场景的最终元素数为 threads × ops_per_thread，见 raw.csv，65536 不是这些场景的插入上限。
- 原包唯一的 legacy benchmark 也在原版/新版本各以 1/4/12 线程、每线程 200000 次运行并检查总和，记录在 `results/legacy/`。其单次结果不计入矩阵的几何平均。
- 正式矩阵及复测期间未并发执行本任务的构建或单元测试。没有固定 CPU 亲和性、频率或清除系统其他进程；置信区间使用按轮配对的中位数比值 bootstrap（2000 次），仅描述本批样本，不能证明普遍等价。
- 当前测吞吐，未测逐操作 P50/P99 或独立容器峰值内存。Map 以外的六个容器未修改，本次运行其全量单元测试；没有凭空声称执行了项目中不存在的六类队列性能套件。

## 复现

```sh
python tools/benchmark.py --exe build-release/cstl_compare.exe --output results --repeats 11 --target 0.12
python tools/benchmark.py --exe build-release/cstl_compare.exe --output results/recheck-string-update --case string:update:12:65536 --repeats 21 --target 0.5
```

Linux/macOS 去掉 `.exe`；多配置构建使用 `build-release/Release/cstl_compare.exe`。完整 JSON/CSV 带每场景实际 operations、所有样本、区间和环境。不同硬件运行结果应另存目录，不覆写本次记录。
